# 会話コンテキストの字数予算（RIT-71）

`createTurnGraph` はモデルへの初回生成・続き・塊の再生成の入力を層ごとの予算に収める。
`compose` で直近窓を決め、`generate` へ渡す。`extend` / `regenerate_chunk` は同じ窓に
独立した追加指示枠を足す。設定を渡さない既存の呼出しにも既定値が適用される。

```ts
const graph = createTurnGraph({
  model,
  store,
  contextBudget: {
    systemChars: 4000,
    recentChars: 8000,
    instructionChars: 2000,
  },
});
```

| 層                                     | 既定上限 | 超過時                                                           |
| -------------------------------------- | -------: | ---------------------------------------------------------------- |
| system（人格・台帳・出力契約・例示等） |     4000 | モデル呼出し前にエラー。人格や契約を途中で切らない               |
| 直近会話（今回の入力を含む）           |     8000 | 古いメッセージから除外。最新一通だけで超える場合はその末尾を残す |
| 続き・再生成の追加指示                 |     2000 | 指示末尾を残す。会話の枠を消費しない                             |

上限の一部だけを上書きできる。system は 0 以上、他は 1 以上の安全な整数が必要。
総上限は各層の上限の合計で、既定値では **14000 字**。空いている枠を他の層へ融通しない。
既存の `@v2/prompt` v0001 が持つ system の UTF-16 4000 単位上限も引き続き適用される。
この既存上限を引き上げる設定ではない。

## 窓と切詰めの契約

- メッセージは古い順で受け取る。今回の利用者入力を必ず最後へ加えてから窓を決める。
- 最新から遡って、本文の合計字数が予算内の連続した窓を取る。古い長文を飛ばして、
  さらに古い短文だけを拾うことはしない。残すメッセージの順序・role は変えない。
- 最新一通が予算を超えた時だけ、その本文の末尾を予算字数まで残す。
  省略マーカーは本文へ挿入しない。`prompt.contextUsage.truncatedLatest = true` で明示する。
  会話 messages では末尾だけを渡す。既存の台帳更新は入力先頭の短い要約を system に残す場合があるため、冒頭情報が全層から消える保証ではない。
- 空の最新入力も user メッセージとして残す。入力・履歴を変更せず、保存へは原文を渡す。
- 字数は **Unicode コードポイント数**。日本語、改行、空白をそれぞれ数え、サロゲート対を
  切断しない。結合文字・ZWJ はそれぞれ一字として数えるため、書記素単位の保証ではない。
- 字数は本文だけを数える。role 等のプロトコル表現やモデルのトークン数とは異なる。
  この予算はモデル固有のトークン上限の保証ではない。
- 極端な長文でも字数判定は予算を一字超えた所で止める。末尾切詰めも予算分だけ遡り、
  原文全体を配列へ展開しない。

`contextUsage` は system / recent / instruction / total の使用量、除外したメッセージ数、
最新入力と追加指示の切詰め有無を返す。初回組立ての値は LangGraph 状態の
`prompt.contextUsage` でも参照できる。SSE や DB 契約は変更しない。
反復語の採集も直近窓の assistant 本文を使い、窓の外の長文を別経路で system へ戻さない。

## 検証範囲

`pnpm --dir packages/engine run test --runInBand` で、空・境界・役割混在・複数層・Unicode・
100万字級の合成一般会話を確認する。fake model とインメモリ store を使い、
generate / extend / regenerate の実際の引数、保存原文、同一 thread の次ターンも検証する。
実 provider・DB 書込み・実キャラ本文・corpus は使わない。

長期記憶の要約・検索・所有者境界・200ターン後の再現性は親 RIT-48 の別 SBI の対象。
store の履歴読出し量や checkpointer の保持量も変更していない。
image 側はスコープ外。変更は `packages/engine` 内のテキストモデルへの入力組立てだけで、
画像生成プロンプト、Novita、R2、画像表示への接続はこのパッケージにない。
完成版アプリ全体・実生成品質・UI 目視の合格をこの試験だけで主張しない。
