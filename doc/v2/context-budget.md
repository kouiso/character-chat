# 会話履歴の容量制限（RIT-71）

モデルへ渡す直近の履歴と、今回のユーザー入力に別々の上限を持たせる。

| 層 | 既定の上限 | 設定場所 |
| --- | ---: | --- |
| システム指示 | 4,000字 | `@v2/prompt` の既存上限 |
| 過去の会話 | 12,000字・40メッセージ | `V2_HISTORY_CHARACTERS` / `V2_HISTORY_MESSAGES` |
| 今回の入力 | 4,000字 | APIの入力検査・engineの独立上限 |

字数はJavaScriptの文字列長（UTF-16コード単位）で数える。トークン数やモデルごとの実測コンテキスト上限とは区別する。

過去の会話は新しい方から連続して採用する。次の1通を加えると予算を超える位置で止め、古い会話を飛び飛びに混ぜたり途中で切ったりしない。単独で予算を超える過去メッセージが直前にあれば、今回は履歴を入れずユーザー入力を渡す。元のD1履歴・画面表示は変更しない。

今回の入力は必ず末尾に含める。上限を超えた入力や不正な設定は、黙って切り詰めずモデル呼出し前に拒否する。履歴上限0は許可し、過去メッセージを送らない。

## 検証

- 200ターンから直近の連続した履歴だけが予算内で選ばれる。
- 過去の1通が10万字でも上限を超えず、今回の入力は欠けない。
- 件数上限、0予算、負数・NaN・無限大・小数を検証。
- LangGraphの実行と保存されたgenerationリクエストで、モデルへ渡すメッセージが選定結果と一致することを確認。

この制限は短期履歴の送信量を制御する。長期記憶・要約による事実保持はRIT-72以降で検証し、ここだけで200ターン後の記憶品質を完了とはしない。
