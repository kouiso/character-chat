# 会話履歴の容量制限（RIT-71）

モデルへ渡すプロンプトを7つの層に分け、層ごとに字数上限を持たせる。

| 層             |             既定の上限 | 設定場所                                        |
| -------------- | ---------------------: | ----------------------------------------------- |
| 1. システム指示 |                4,000字 | `@v2/prompt` の既存上限（`MAX_SYSTEM_CHARS`）   |
| 2. 要約        |                2,500字 | `V2_SUMMARY_CHARACTERS`                         |
| 3. 長期記憶    |                2,000字 | `MEMORY_CONTEXT_CHARACTERS`（固定・pin込み）    |
| 4. 資料        |                4,000字 | `DOCUMENT_CONTEXT_CHARACTERS`（固定）           |
| 5. 利用者像    |                2,000字 | `USER_PERSONA_MAX_CHARS`（固定）                |
| 6. 過去の会話  | 12,000字・40メッセージ | `V2_HISTORY_CHARACTERS` / `V2_HISTORY_MESSAGES` |
| 7. 今回の入力  |                4,000字 | APIの入力検査・engineの独立上限                 |

字数はJavaScriptの文字列長（UTF-16コード単位）で数える。トークン数やモデルごとの実測コンテキスト上限とは区別する。

過去の会話は新しい方から連続して採用する。次の1通を加えると予算を超える位置で止め、古い会話を飛び飛びに混ぜたり途中で切ったりしない。単独で予算を超える過去メッセージが直前にあれば、今回は履歴を入れずユーザー入力を渡す。元のD1履歴・画面表示は変更しない。`buildConversationContext` が境界の唯一の根拠で、含めた最古のメッセージのターンを `oldestIncludedTurn` として返す。

要約層は L2 サマリーを先に入れ、残りの枠へ L1 を新しい順に詰める。見出し行と区切り行も予算に含め、途中でエントリを切らない。枠を超える古い L1 は捨てる。

今回の入力は必ず末尾に含める。上限を超えた入力や不正な設定は、黙って切り詰めずモデル呼出し前に拒否する。履歴上限0は許可し、過去メッセージを送らない。

`V2_HISTORY_CHARACTERS` / `V2_HISTORY_MESSAGES` / `V2_SUMMARY_CHARACTERS` が未設定・空文字なら既定値を使う（wranglerの `env.<名前>.vars` は最上位の `vars` を引き継がないため各環境に書く）。値があって0以上の整数として読めない場合（負数・小数・`abc`・前後の空白など）は既定値へ逃がさず、`POST /api/chat` がジョブを積む前に500を返し、`context_budget_config_invalid` をログへ出す。

固定の層上限を超えるブロック（システム指示・長期記憶・資料・利用者像）が紛れた場合は生成を開始せず `PromptBudgetExceededError` で失敗させ、`prompt_budget_exceeded` イベントに層ごとの字数だけ記録する（本文は出さない）。この失敗は決定的なのでリトライしない。

## 記録

1ターンごとに `v2_generation.context_usage_json`（nullable）へ層ごとの字数と `oldestIncludedTurn`、`omittedHistoryMessages` を保存する。`request_json` の形は変えない。

## 検証

- 200ターンから直近の連続した履歴だけが予算内で選ばれる。
- 過去の1通が10万字でも上限を超えず、今回の入力は欠けない。
- 件数上限、0予算、負数・NaN・無限大・小数を検証。
- LangGraphの実行と保存されたgenerationリクエストで、モデルへ渡すメッセージが選定結果と一致することを確認。

この制限は短期履歴の送信量を制御する。長期記憶・要約による事実保持はRIT-72以降で検証し、ここだけで200ターン後の記憶品質を完了とはしない。
