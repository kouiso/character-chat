# v2再構築の実装・検証順序

2026-10-26。RIT-9はCanceled。現在のRIT-43〜58と配下SBIを受入条件とし、競合機能RIT-126〜136はこの基盤に載せる。旧`src/`と`functions/`を先に拡張する進め方は採らない。

## 1. 入口と実行環境（RIT-43 / 44 / 59 / 62）

- TanStack StartをCloudflare Vite plugin経由でworkerd上に載せる。
- 全リクエストは独自Worker入口でBASIC認証後に静的配信・SSR・APIへ分岐する。資格情報が未設定なら503、認証不正なら本文なし401。`run_worker_first=true`、応答は共有キャッシュ禁止。
- 資格情報はWorker secrets。コード・URL・ログへ出さない。workers.devとversion URLは既定で無効。開発用の固定モデルは`APP_ENV=test`との両条件でのみ有効。
- D1/R2はWorker bindingsを使う。Node用`getPlatformProxy`は検証CLIに限り、アプリ本体から読み込まない。DB操作はサーバー専用モジュールと`@v2/db`へ集約する。
- ローカルの成功は本番合格と区別する。実モデル・本番URL・戻し操作の実測前に親PBIをDoneにしない。

## 2. 受付・生成・再接続（RIT-46 / 83 / 87 / 90）

- 1会話につき1個のDurable Object。ブラウザは送信前にconversationIdとrequestIdを作り、未完了の送信を端末に保持する。
- DOはalarmを予約してからrequestIdと入力のハッシュを同期的に永続化する。受付だけが残り実行されない窓を作らない。同じID・同じ入力は既存の処理を返し、同じID・違う入力は409。同じ会話の異なる処理が進行中なら409。
- alarmが生成を担当する。SSEの切断は閲覧の中断のみとし、生成は中止しない。完了したイベントをDOに保存し、連番カーソルから再送する。
- D1保存後・DO完了記録前の障害では、受付時のターン番号とD1の確定履歴を照合する。既に保存済みなら再生成しない。
- 処理途中の出力は確定履歴にしない。生成の実行回数に上限を設け、失敗は永続的な状態としてUIに返し、同じ受付の明示再試行を提供する。
- D1でuser/character/conversationの所有境界を確認し、違うキャラの会話IDを渡しても履歴を読み書きできないようにする。

## 3. データ移行（RIT-45）

- 本番への書込みより先に資源・スキーマ・件数を読み取り、スナップショットを別環境へ復元して検証する。
- 旧IDを保持してキャラ・会話・メッセージ・記憶の対応を記録する。件数だけでなく本文ハッシュ、参照、順序、削除状態を照合する。
- 認証・切断再開・所有境界を通した後、並行運用期間を計測する。既存アプリ停止を移行スクリプトに含めない。

## 4. 記憶・版・表示・競合機能

RIT-48/49/50（記憶と削除・評価）、52/53/54（キャラ版・資料・物語）、55/47（再開・段階配信）、57/58（能動会話・複数キャラ）の順で依存を解く。競合機能の保存先・権限・失敗時処理はこの境界へ接続する。各チケットはDB・API・UI・障害試験が揃ってから完了とする。

## 検証の記録

実行環境、commit、入力条件、期待値、実測、未検証を区別する。ローカル固定モデルの試験で実AIの会話品質を合格にしない。資格情報・会話本文・本番スナップショットは公開リポジトリへ記録しない。

### ローカルでの再現

`apps/v2/.dev.vars`に開発用BASIC資格情報と`APP_ENV=test`、`V2_FAKE_MODEL=1`を設定する。実資格情報をコミットしない。

1. `pnpm --filter @v2/app seed:local`
2. `pnpm v2:dev`を起動する。
3. 別端末で`pnpm --filter @v2/app verify:runtime`を実行する。

検証スクリプトはlocalhostかつ固定モデルのhealth応答を必須とし、実AIを呼ばない。認証拒否の本文0バイト、通信切断後の完了、同一受付の再送、異なる入力の409拒否、連番カーソルからの再接続を確認する。
