## 1. 何を作るか

## 2. 全体の形

### 2.1 構成図

```text
  ブラウザ / PWA（携帯優先・PC も）
  └ 画面: TanStack Router の route ＋ assistant-ui の会話部品 ＋ Claude Design のトークン
        │  HTTPS（全部 BASIC 認証）・SSE で返事を受け取る
        ▼
  ┌──────────── Cloudflare Worker（1 本。TanStack Start ＋ 独自の入口ファイル）────────────┐
  │ 入口: BASIC 認証（静的ファイルも run_worker_first で通す）                              │
  │ server routes（外向きの口）: /api/chat /api/character /api/memory /api/media ...        │
  │ server functions（画面からだけ呼ぶ口）                                                  │
  └──────┬───────────────┬──────────────────┬────────────────────┬─────────────────────┘
         │会話ごとに1個   │キャラ・記憶の読書き │画像・資料ファイル     │急がん仕事
         ▼               ▼                  ▼                    ▼
  ChatRoom DO        D1（正本）           R2                    Queue
  ・受け取りを保存   ・キャラ/版/資料目録   ・アバター・生成画像  ・記憶の抜き出し
  ・alarm で生成     ・会話/メッセージ/枝   ・設定資料の原本      ・埋め込み・要約
  ・送る予定表       ・記憶/要約/台帳      ・取り込んだ元 JSON   ・画像/音声の生成依頼
  ・話しかけ予定     ・ロアブック/情報欄    ・音声               │
  （SQLite・alarm 1 本を予定表で回す）・FTS5（単語検索）                    ▼
         │                               Vectorize ◀── Workers AI bge-m3（1024 次元）
         ▼                               （user×キャラで区切る。記憶・資料・履歴）
  engine（LangGraph.js）
  ・1 ターンの流れ（§4.2）  ・抜き出しの流れ  ・要約の流れ  ・話しかけの流れ  ・同じ場の話者選び
         │
         ▼
  AI Gateway（記録・使いすぎ上限） ─▶ OpenRouter（OpenAI 互換の口 1 本）
                                       既定 deepseek/deepseek-v4.1-flash-1017（本家 DeepSeek を除外）
                                       逃げ道1 v4.1-flash を Venice 固定 / 逃げ道2 dolphin-mistral venice edition
  画像・動画・音声の生成先（v2）: 外部の生成 API（既存 RIT-21 の Novita/Runware 線）を Queue から呼ぶ
```

読み方: 1 通は Worker の入口で認証され、その会話の DO に渡る。DO は受け取りを保存して alarm をかけ、返事作りは alarm の中で engine が回す。画面を閉じても止まらん。重い・急がん仕事は全部 Queue に落とす。

### 2.2 層の表（持ち主は 1 層 1 人）

| 層 | 持ち主（ここだけが書く） | 使う既製の仕組み | 知らんでええこと |
|---|---|---|---|
| 画面 | `apps/v2/src/routes`・`component` | TanStack Router（route・loader・search params）、assistant-ui（スレッド・入力欄・再試行・自動スクロール）、Claude Design のトークン（CSS 変数） | モデル名・DO・D1 の形 |
| 外向きの口 | `apps/v2/src/server`（server routes） | TanStack Start の server routes / server functions、zod で入力検査 | LangGraph の節の中身 |
| 鍵 | Worker の独自の入口ファイル 1 か所 | Cloudflare の `run_worker_first`・`workers_dev: false`・`preview_urls: false`・secret | 画面・会話 |
| 会話の進行 | ChatRoom DO（1 会話 1 個） | DO の SQLite・alarm・入力ゲート（同時に 1 処理） | プロンプトの組み方 |
| 頭脳 | `packages/engine` | LangGraph.js `StateGraph`、`@langchain/openrouter`、`@langchain/textsplitters` | HTTP・認証・画面 |
| 品質 | `packages/judge` | 既存の `splitChunks`・判定 52 本 | モデルの選び方 |
| 指示文 | `packages/prompt` | 版つき指示文（v0001〜）、SceneLedger | 保存先 |
| 正本データ | `packages/db`（D1） | D1・FTS5・migration | 生成 |
| 検索 | engine の `retrieve` 節だけが読む／Queue の抜き出しだけが書く | Vectorize（名前空間・絞り込み項目）、Workers AI bge-m3 | 画面 |
| 後回しの仕事 | Queue の受け手 1 本 | Cloudflare Queues（やり直し付き） | 画面 |
| AI の口 | engine の model 1 実装 | AI Gateway → OpenRouter（OpenAI 互換） | 各社の専用 SDK |

不変条件（破ったら設計違反）:
1. 記憶の書き手は 1 つ（engine の memory 書き込み口）。画面の「覚えといて」ボタンも同じ口を呼ぶ。
2. 記憶を消す時は D1・Vectorize・要約の 3 か所。要約に残っとったら要約を作り直す。
3. アダルト区分の会話は本家 DeepSeek に送らん（設定とテストで固定）。
4. 外から呼べる口は全部、入口の BASIC 認証を通る。
5. 画面にモデル名・実行先・トークン数を出さん（管理画面だけ）。

## 4. 記憶・RAG・LangChain/LangGraph の設計

### 4.1 記憶の層（10-26 設計の 6 層に 3 層足す）

| 層 | 中身 | いつ作る | どこ | 範囲 | 出どころ |
|---|---|---|---|---|---|
| ① 短期の窓 | 直近の会話そのまま | 毎ターン | D1 `v2_message` | 会話（枝ごと） | 10-26 |
| ② 巻き取り要約 | 古い所を章ごとに。古い要約はまとめ直す（2 段） | 窓から押し出された分がたまったら | D1 `summary` | 会話（枝ごと） | 10-26、Mi5 |
| ③ 長期の事実 | 呼び名・好み・約束・関係・出来事を 1 件ずつ。種類・重要度 1〜10・正しい期間・置き換え先・**`origin`（stated＝局長が言うた／inferred＝AI が推した）**・固定 | 毎ターン後に Queue で | D1 `memory_item` ＋ Vectorize | 局長×キャラ | 10-26、Ve5、スター E |
| ④ 物語の台帳 | 場所・時刻・服・人物・持ち物・出来事 | 毎ターン | D1 `v2_ledger` | 会話（枝ごと） | 10-26、Sa13 |
| ⑤ 設定資料 | 1,200 字ずつ 200 字重ねた塊 | 取り込んだ時 | R2 ＋ Vectorize | キャラ | 10-26、Ve2 |
| ⑥ 会話履歴の検索 | 過去の会話を数ターンずつ | 要約を作る時 | Vectorize | 局長×キャラ | 10-26 |
| ⑦ **ロアブック** | キーワード → 説明。会話にその語が出た時だけ差し込む。複数キャラに接続できる | 作者が書いた時 | D1 `lorebook` / `lorebook_entry` / `lorebook_link` | ロアブック単位（接続先へ反映） | Ze3, Ze19 |
| ⑧ **インフォボックス** | 背景（日時・場所・天気・状況）とキャラの状態（気分・体調・服装・ポーズ・目標・関係・本心・持ち物）。台帳④から**画面向けに抜いた写し**で、持ち主は④ | 毎ターン（台帳の更新と同じ節） | D1 `v2_ledger` の列 | 会話（枝ごと） | Ze7 |
| ⑨ **プロフィールカード** | ③のうち「局長について」「関係」を固定の項目で並べた見え方。保存は③のまま、新しい表は作らん | 画面を開いた時に組む | ③から読むだけ | 局長×キャラ | Mi5 |

決め事:
- ⑦ と ⑤ は分ける。⑤は「意味が近い物を探す」、⑦は「語が出たら必ず入れる」。働きが違うので 1 つにまとめん（10-26 設計で未決やった所の答え）。
- ⑧ と ⑨ は「見え方」であって新しい正本ではない。正本は④と③。持ち主を増やさんため。
- 通常チャット用の別記憶（Ve7）は、「キャラなしの相手」を 1 体の特別なキャラとして扱えば③がそのまま使える。別の仕組みは作らん。
- 枝（M4）と記憶: ①②④⑧は枝ごと（分岐した先で別の出来事になる）。③⑥は局長×キャラで共有（分岐しても局長の好みは同じ）。ただし枝の中で生まれた出来事の事実は `conversation_id` と枝 id を持たせ、別の枝の検索では点を下げる。
- 全消去（Mi5 のリセット）は ③⑥ と要約を、そのキャラの分だけ 3 か所から消す（不変条件 2）。

### 4.2 1 ターンの流れ（今ある 11 節に足す所）

今の `packages/engine/src/graph.ts`: `intake → ledger_update → retrieve → compose → generate → extend → chunk → judge_chunk → regenerate_chunk → emit → persist`。`retrieve` は今は空（`retrieved: []`）。

```text
intake
 → ledger_update（④台帳と⑧情報欄を更新）
 → retrieve（③事実＋⑤資料＋⑥履歴を Vectorize と FTS5 で探す。⑦ロアブックは語の一致で引く）
 → compose（層ごとの字数予算。会話の感じ M6 の札をここで指示文に変える）
 → generate（OpenRouter。逃げ道は model 層の中だけ）
 → extend → chunk（描写・セリフ・心の声の塊）→ judge_chunk ⇄ regenerate_chunk
 → suggest（足す。M5: 選択肢・おすすめ返信。札で ON の時だけ、軽い設定で 1 回）
 → emit（送る予定時刻つき）
 → persist（D1 に保存し、Queue に「抜き出し・埋め込み・要約が要るか」を積む）
```

別の流れ（同じ engine に置く。LangGraph の `StateGraph` を 1 本ずつ）:

| 流れ | 起こす所 | 節 |
|---|---|---|
| 抜き出し | Queue の受け手 | 直近の往復を読む → 事実の候補 → 既存と突き合わせ（新しい方が勝つ・古い方は置き換え済み）→ `origin` を付ける → D1 と Vectorize に書く |
| 要約 | Queue の受け手 | 窓から押し出された分 → 章の要約 → 古い要約のまとめ直し |
| 話しかけ | ChatRoom DO の alarm | 入切・静かな時間・回数を見る → ③と④から「この前の続き」の種を選ぶ → 1 ターンの流れの `compose` 以降を流用 |
| 同じ場の話者選び（v2） | 1 ターンの流れの頭 | 誰が話すか選ぶ → そのキャラの③だけを引く（混ぜん） |

LangGraph をどこまで使うか:
- 使う: `StateGraph`（節と条件つきの辺）、`Annotation` の状態、ストリーミングの仕組み（`emit` が既に使っとる）。
- 使わん: checkpointer（保存役）。理由は §0 の 3。自作の保存役を `@langchain/langgraph-checkpoint-validation`（1.2.0）で検査する道はあるが、要るのは「人が途中で承認して再開する」流れが出来た時だけ。今は無い。
- LangGraph が Workers の本番で動くかは未実測（10-26 設計 §2.4、SBI-02-1）。動かんかった時の代わりも 10-26 設計のまま（同じ節を手で書く）。

LangChain から借りる部品（`npm view` で確認、2026-10-31）:

| `@langchain/openrouter` | repo に ^0.4.11 | モデルの口 | OpenAI 互換 1 本（スター D） |

### 4.3 探し方（RAG）

- 点数 = 意味の近さ × 重要度 × 新しさ。置き換え済みは出さん。`inferred` は点を下げる。
- 意味の検索（Vectorize）と単語の検索（D1 の FTS5。D1 は FTS5 に対応、https://developers.cloudflare.com/d1/sql-api/sql-statements/ 2026-10-31 閲覧）を両方引いて順位を混ぜる（Venice の Memoria と同じ考え。短い問いは単語を重く）。
- Vectorize の区切り: 名前空間 `user:{id}:char:{id}`、絞り込み項目 `kind`（fact / lore / history）・`conversation_id`・`branch_id`。
- 字数予算は層ごと。数字は記憶の試験（RIT-50）で測って決める。今は決め打ちせん。
