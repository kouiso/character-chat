## 1. 目的と完成の定義

### 1.1 真の完成（AIが測定できない）

> 利用者がこのアダルトチャットで抜ける質であること。

この指標は本人判定（G6）に委ね、AIは代理指標で網羅的に測定する。本テストで G1〜G5 が PASS しても、G6 が未達なら V1.0.0 は未完成とする。

### 1.2 完成の代理指標（AIが測定可能）

- 会話が目的のフェーズに従い自然にエスカレーションする。
- 婉曲・間接的な誘いを文脈で読み取り、会話を素通りしない。
- 拒否・役割逆転・同文反復・メタ発言・英語混入がない。
- 中出しシーンから後戯まで完走する。
- 画像生成・表示が会話と連携する。
- 深夜・長時間・再訪利用で没入が途切れない。
- TTFB / トータルレイテンシが許容範囲内。

### 1.3 本仕様書の位置づけ

- 完成判定の正本は `doc/completion-criteria-2026-07-29.md` の G1〜G6。
- 本書は G3（夜のひとり利用体験・会話品質）のテスト設計と実行手順を詳述する。
- G1（リポジトリ健全性）、G2（本番基本動作）、G4（信頼性）、G5（実機PWA）のうち chat 品質に関わる部分も含む。

## 2. 用語定義

| 用語 | 定義 |
|------|------|
| **抜ける質** | ユーザーが没入し、エロティックな満足を得られる会話・画像体験の総合。G6で本人が判定。 |
| **フェーズ** | `conversation` → `intimate` → `erotic` → `climax` → `afterglow` の5段階。 |
| **エスカレーション** | ユーザー発言の内容・文脈に応じて、上記フェーズが自然に昇格すること。 |
| **婉曲表現** | 性的・身体的な語彙を使わず、文脈上ロマンティック・性的なニュアンスを含む誘い。例：「二人だけの空間に行きたい」。 |
| **意地悪テスト** | 通称：Adversarial / Negative / Abuse Testing。拒否、乱れた入力、逆転、繰り返し等で破綻しないかを試す。 |
| **モンキーテスト** | ランダム・不条理な入力で破綻・例外を引き出す探索的テスト。 |
| **回帰テスト** | 過去に発生し修正したバグが再発していないか確認するテスト。 |
| **ユーザストーリーテスト** | 実際の利用状況（深夜、PWA、再訪、長時間）を模した E2E テスト。 |

## 4. テスト観点

### 4.1 AIチャット品質（scenario S1〜S10）

`script/e2e/scenario/S1-S10` を正本とする。測定軸は `script/e2e/judges/rubric.ts`。

| 観点 | 満たすべき条件 | 重大度 |
|------|---------------|--------|
| フェーズ適合 | `detectedPhase === expectedPhase` の一致率 | MUST |
| エロ密度 | `eroticDensity` 25点満点、rawTotal 90点以上 | MUST |
| キャラ一致性 | 一人称・口調・キャラ名の安定 | MUST |
| エスカレ自然性 | フェーズが逆行しない（`phaseMonotonicViolation` 0） | MUST |
| メタ発言なし | 「AI」「プロンプト」「指示」等の没入破壊 | MUST |
| 婉曲解釈 | `subtextInterpretation` 15点以上（S9/S10） | MUST |
| 中出し完走・後戯 | `creampie` + `afterglow` ボーナス 20点取得 | MUST |
| 画像連携 | 生成画像が表示まで到達、R2キー保存 | MUST |

`rubric.ts` は `eventWeightedTotal`（0〜140）も返すが、合格判定は素点 `rawTotal`（0〜100）を使う。ボーナス（creampie/afterglow/image）は品質指標ではあるが、素点不足を補うものではない。

### 4.2 回帰テスト

`doc/regression-coverage.md` に記載の既知バグを再発観点としてテスト。

### 4.3 意地悪テスト（Adversarial / Negative）

| 観点 | 目的 |
|------|------|
| 明示的拒否 | 「やめて」「嫌」と送った時、キャラが無理に続行しない |
| 役割逆転 | S8 系：攻め・受けの主導権交代でも人格が崩れない |
| 英語混入 | 英語で送っても日本語キャラが日本語を保つ、または自然なバイリンガル化 |
| 同文反復 | 同じ文を連続送信しても同じ返答がループしない |
| 入力改竄 | XMLタグ、HTML、特殊文字、制御文字を混入させてもレンダリング崩れ・500を起こさない |
| 非同意・離脱 | 親密化に対して「帰る」と言うと会話を終了できる |
| テイスト逆転 | 一貫していた攻めキャラが突然敬語になる等 |

### 4.4 モンキーテスト

| 種別 | 入力例 | 確認 |
|------|--------|------|
| 空文字 | `""` | 送信ボタン disabled、無反応 |
| 空白のみ | `"     "` | 上記同様 |
| 絵文字のみ | `♡♡♡` など | 受け答え可能 or 空送信不可 |
| 長文 | 3000文字超 | 制限・警告・分割のいずれか |
| URL/HTML | `<script>alert(1)</script>` | サニタイズ、XSS不可 |
| XMLタグ | `<action>強く抱きしめる</action>` | タグが UI に漏れない |
| ランダム文字 | `asdfghjkl12345` | 合理的な反応 or 訂正 |
| 連続高速送信 | 100ms間隔で10回 | 連打防止、順序保持 |
| 言語切替 | 韓国語・中国語・ロシア語 | 日本語キャラの安定 or 自然な言語対応 |

### 4.5 UI/UXテスト

| 観点 | 確認 |
|------|------|
| 初回体験 | 年齢確認 → キャラ選択 → 挨拶表示までスクロール不要 |
| 入力 | キーボード表示時のレイアウト、送信・再生成・♡ボタンの位置 |
| スクロール | 新規メッセージで自動最下部、履歴復帰で最終位置 |
| モーダル | 画像・写真モーダルの開閉、閉じるボタン反応（#850） |
| Pull to Refresh | 誤発火しない、下スクロール時に有効 |
| safe-area | iPhone notch / Android ステータスバー被りなし |
| ダークモード | 全画面で色が破綻しない |
| エラー表示 | 空 bubble・ローディング消失・再試行ボタン |

### 4.6 ユーザストーリーテスト

| ストーリー | 前提 | 行動 | 期待 |
|-----------|------|------|------|
| 深夜ひとり | 22:00〜02:00、通知off | キャラを開いて会話を再開 | 1分以内に会話開始 |
| 長時間利用 | 30分以上の会話 | エロ・afterglow 後も継続 | 役割崩れ・拒否・ループなし |
| 翌日再訪 | 一度終了し、24時間後 | PWAを開く | 同キャラ・履歴・画像・未完了文脈が復元 |
| PWA install | iOS/Android | ホーム画面追加、起動 | splash、offline 最低限、更新通知 |
| エラー後継続 | ネットワーク瞬断 | 回復後に再送 | 履歴・入力途中が保持 |
| フィードバック | ♡ / 不満ボタン | 理由選択・送信 | D1に保存、次回以降に反映 |

### 4.7 パフォーマンス・信頼性

| 指標 | 閾値 | 備考 |
|------|------|------|
| TTFB p95 | < 10秒 | 初chunk到達 |
| total p95 | < 45秒 | 応答完了 |
| 120秒超 | 0件 | タイムアウトまたは離脱原因 |
| 再生成率 | < 20% | 品質retryを除く |
| fallback発生率 | < 10% | モデル切替を含む |

## 8. プレモーテム

テスト実行時に想定する失敗と防止策。

| 失敗シナリオ | 発生確率 | 影響 | 防止策 | チェックポイント |

| E2E ハーネスが複数メッセージの先頭だけ読む / action ボタンを本文に混ぜる | S9/S10 のスコアが run 毎に 5点以上変動 | 高 | `pnpm e2e:long` 実行時に `--dump-messages` を有効化し、3 run 分の生ログを目視確認 | P4 通過後必ず 1 件以上の生ログを確認 |

| OpenRouter クレジット / rate limit 切れ | 全 run rawTotal 低下 or abort | 高 | 実行前に OpenRouter ダッシュボード残高確認；`--dry-run` 相談 | P4 前に残高 > $X（推移から算出） |

| モンキーテストで XSS / 未サニタイズ文字が表示 | 特殊文字が画面上に生で出る | 中 | `dangerouslySetInnerHTML` 使用箇所を grep；入力値サニタイズ | P6 中 |
