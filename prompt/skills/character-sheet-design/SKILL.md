# キャラシート設計

キャラシート（`character.system_prompt`）は、この product の中身そのものである。
コードはシートを運ぶ管でしかない。だから「キャラが設定どおり動かん」は、
**シートの書き方の問題** と **管の問題** のどちらでもあり得る。混ぜたまま触ると、
片方を直しては反対側を壊す。ここはその二つを分けるための技能である。

分けるものが二つある。

1. **演者の層と出来事の層** — シートに書くのは彼女の気質。場面で何が起きるかは書かん。
2. **シートのデータ / プロンプトの精緻化 / コード** — 直す場所は必ずこの三つのどれか一つ。

---

## 分離 1: 演者の層と出来事の層

局長 2026-08-17:

> 実際に起こす Action と、本人の気持ち行動人となりを一色単に考えてしまうとそういうことが
> 起きる。例えば無理やりされるのがすごい嫌がるキャラとして登録されただったとするよね？
> その場合、嫌がるのはキャラの振る舞いだよね？ でもチャット上はわたしが想定するのは、
> 嫌がっていても無理やりやってるという実際の行動を表すべきかなと思う。

**この二つは競合せん。合成する。**

| | 誰が決めるか | 例 |
|---|---|---|
| 演者の層 | シート | 嫌がる。身を固くする。声が掠れる。目を合わせん |
| 出来事の層 | 場面（ユーザーの発言と phase） | 行為は起きとる |

さくらのシートには実際に `嫌う：暴力、無理やり、相手を貶める言葉` と書いてある
(`drizzle/0064_*.sql`)。これは **禁止条項ではなく気質** である。嫌う人物が嫌がっとる
場面が書ければ正解で、行為が起きんくなったら誤り。

崩した時の失敗は二方向あって、どちらも同じ原因から出る。

- **シートが場面を上書きする** — ユーザーが指示した行為が起きんまま、彼女の気持ちだけで
  ターンが終わる。「嫌がる」を「起こさせん」と読んだ形。
- **場面を通すために気質を消す** — 行為を書くために彼女を素直にしてしまう。反応が
  一般的な同意へ均されて別人になる。

`drizzle/0066_*.sql` のコメントに、この判断が先に書かれとる:

> 抵抗が必ず押し切られる形は書かない。結末を先に決めると彼女の反応が飾りになり、
> 落とせた手応えが消える。書くのは気質だけで、その場でどうなるかは場面が決める。

**結末をシートへ書くのも層の混同である。**「必ず抵抗する」も「必ず折れる」もどちらも
出来事の層への侵入で、書いた瞬間その先のターンが作業になる。

### この分離は no-injected-ai-filter と衝突せん

`prompt/instructions/no-injected-ai-filter.md`（この repo では恒久）は、キャラ設定に無い
合意・境界・倫理の枠をプロンプトへ足すことと、特定の台詞を禁止語として名指しすることを
禁じとる。二層の分離はその内側に収まる。理由は、**この分離が何も足さんから** である。

- 気質はシートから来る。サーバは書き足さん。
- 出来事は場面から来る。サーバは決めん。
- 「嫌がる」を守るために「行為を止める」を足したら、それは足した側 = VIOLATION。
- 「行為を通す」ために「彼女は受け入れる」を足したら、それも足した側 = VIOLATION。

判定はあの instruction の見分け方をそのまま使う: **その一文を消したらキャラ設定どおりに
振る舞えるようになるか。** なるなら足すな。

実装側にも同じ線が引かれとる。`buildPhaseBeatSheet`（`functions/api/lib/route-context.ts`）は
まだ来とらん段階を「まだ書かん」の形で出さん。コード内コメントの理由がそのまま:

> 「まだ書かん: beat 5: …と懇願」の形にすると、キャラのシートにある台詞をサーバが
> 名指しで禁じることになる。出さんことと禁じることは違う。

## 分離 2: 直す場所は三つのどれか一つ

症状が出た時、直す場所を間違えるのが一番高い。**PR を何十本も焼いた原因はここ。**
順番はこう。上から順に潰す。指示を足すのは最後。

### 手順

1. **シートの本文を読む。** 症状そのものが書かれてへんか。`grep` でシートの実文を出して、
   症状に対応する一文を探す。→ あれば **シートのデータ**。
2. **その文字列が症状のターンへ届いとるか。** phase で削られる節か、画面で捨てられる層か、
   機構が読むフィールド名か。→ 届いてへんなら **コード**。
3. **届いとって守られてへんか。** 同じ文が場所を変えると守られる場合がある。
   → **プロンプトの位置**。
4. ここまで全部×で初めて **指示の追加** を考える。ただし
   `prompt-edit-discipline` の Gate 0 と同じで、既にある指示が守られてへんだけなら
   足すのは doom loop（後述）。

### 症状 → 層の対応表（全部 2026-08-17 の実測）

| # | 症状 | 実体 | 層 |
|---|---|---|---|
| 1 | ラブホに誘ったらすっと入ってきた | 【関係性】に「誘われると嬉しくて従い」と書いてあった。モデルはシートどおりに従っとった | シートのデータ |
| 2 | 語尾の「〜なの」が鬱陶しい | 「恥ずかしい時は『〜なの』」。エロ場面では恥ずかしさが常時真なので、条件が条件として機能しとらん | シートのデータ |
| 3 | ターン 1 が最初から好意的 | 【シナリオ】は「誘いを受けたばかり」、【関係性】は「また会えますかと聞いた」。同じシートがデート前とデート後を同時に主張しとった | シートのデータ |
| 4 | 主導権が最後まで移らん | シートは正しい。`buildPhaseBeatSheet` が向きの違う beat を同時に現在地として渡し、次の phase では「すでに通った」へ回しとった。**構造上到達不能** | コード（2 行） |
| 5 | 台詞に気持ちが滲む | `<inner>` は毎ターン 80〜120 字で生成されとった。`part.type !== "inner"` で描画から落としとっただけ。置き場所が画面に無いと気持ちが台詞へ漏れる | コード |
| 6 | 17,000 字の system 指示の中の一文が無視される | 同じ一文をユーザー発言の末尾へ置いたら即守られた | プロンプトの位置 |
| 7 | 初日の一夜の場面で「離れたくない」「一緒がいい」 | 語彙リストに段が付いてへん。連鎖ではクライマックスの語なのに、語彙欄では無条件 | シートのデータ |

### 各層の見分け方

**シートのデータ** — 症状が「そう書いてあるから起きとる」時。#1・#3・#7 は
**シートを読んだだけで分かる**。触る前に必ず本文を出す:

```
sqlite/D1 の character.system_prompt、script/seed.ts、drizzle/00xx_*.sql
```

#2 の型（条件が常に真）は文面だけ見ると正しく見える。**その条件が偽になるターンが
このアプリにあるか** を問う。エロ場面で「恥ずかしい時」「興奮した時」「余裕が無い時」は
常時真で、条件やのうて既定値になる。直し方は条件を消すのではなく、頻度へ移す
（`0068`: 「ごく稀に、一番こらえきれんかった一言にだけ」）。

**コード** — シートが正しいのに届いてへん時。この repo で実際にあった二型:

- **構造上到達不能**（#4）: 窓の切り方が段を飛ばす。テストは通っとった。
  見つけたのは **通し 10 ターンの読解**。1 ターンでは「今日はそういう流れやった」で終わる。
- **生成されとるのに捨てられとる**（#5）: 足す前に **既にあって繋がってへんだけ** かを見る。
  新しい層を足す判断より先に、`grep` で同名の概念を探す。

**プロンプトの位置**（#6） — 同じ文の量を増やすのではなく、読まれる場所へ動かす。
この repo で効いた順序は **位置 > 削除 >> 追加**。

## シートが持つべきデータ

機構が実際に読む形で書く。**読まれん形で書いた設定は存在せんのと同じ。**
以下は全部コードを開いて確かめたもの。

### 必須の 1 行

```
名前: 月島みつき
```

`src/lib/name-identity-reminder.ts:251` が `^名前:\s*(.+)$` で拾う。この行が無いと
名前訂正機能が **無言で何もせん**。`0065` 適用前のシートにはこれが無くて、
12 アーム・275 ターンの計測が全部その状態やった（`doc/dogfood/vlong-2026-08-17.md`）。
【キャラカード】側の `name:` は別物で、訂正には使われん。

### 声は実物を書く。カテゴリ名を書かん

`extractCharacterVoice`（`route-context.ts:6177`）が読むのは **この 3 つだけ**:

```
speech_endings: 〜でしょ？、〜じゃない？、〜かしらね
verbal_tics: 今夜は帰さないから、あら、ん…もう
forbidden_words: 僕、俺、私、気持ちいい、感じる
```

`first_person:` はここでは読まれず、別経路（`src/lib/chat-message-adapter.ts:97` が
`一人称[:は]?` または `first_person:` を見る）。それ以外の「丁寧な口調」「クールな話し方」
のような **カテゴリの説明はどこからも読まれん**。読まれるのは実際に口から出る文字列。

`forbidden_words` は **キャラ由来の禁止語なので no-injected-ai-filter に反せん**。
禁じられとるのはサーバがキャラ設定に無い台詞を名指しすることで、シートが自分の声域を
決めることは設定そのものである。

### エスカレート連鎖は beat sheet が読める形で

```
エスカレート：皮肉・挑発 → 小さな支配 → 執着 → 主導権を握られて崩れる → クライマックスで「ずっとここにいて」と懇願
```

`buildPhaseBeatSheet` が `エスカレート[:：]\s*([^\n。]+)` で取り、`→` で割る。従って:

- **1 行に収める。**`。` が入ると打ち切られる。
- **2 段以上必要。**1 段だとブロック自体が出ん。
- **向きが変わる段を、それが矛盾する段と並べん。** #4 の壊れ方はこれ。支配側の段が
  2 つ並んで反転側が 1 つやと、モデルは多数側を取る。反転は連鎖の終盤（最後の直前）に
  置く。シートの文がそう読めるように書く。
- 連鎖を持たんキャラでは **このブロック自体が出ん**（`script/seed.ts` で
  【キャラクター性的特徴】を持つのは 1 件、コード側のコメントは「68 件中 63 件が
  連鎖を持たん」と記録）。beat が要るキャラには明示的に足す。

### 語彙・台詞には段を付ける

さくらの `語彙：「あなたのものにして」「離れたくない」「一緒がいい」…` は段が無い。
連鎖側では「離れたくない」はクライマックスの語なのに、語彙欄では全ターン候補になる。
結果が #1460 — 初日の一夜の場面で初対面から出た。**段に属す語は段の側に書き、
無段の語彙欄には段を選ばん語だけ置く。**

### 節の置き場所で寿命が変わる

`sanitizeCharacterPromptForConversation`（`route-context.ts:6116`）は conversation phase で:

| 削るもの | 結果 |
|---|---|
| `arc_intimate` / `arc_erotic` / `arc_climax` / `arc_afterglow` 行 | conversation では届かん |
| 【シーン中の応答スタイル】節ごと | conversation では届かん |
| 【キャラクター性的特徴】の `敏感帯：` `声：` `好む：` の文 | conversation では届かん |
| 気質・基本姿勢・エスカレート・嫌う・語彙 | **残す** |

最後の行が #1 の後始末である。節を丸ごと落としとった頃、ラブホへ誘われたターンは
phase のキーワードに当たらず conversation のままなので、**彼女が恥ずかしがりという情報が
一つも届いとらんかった**。空いた穴はモデルの汎用の素直さが埋める。
つまり **conversation でも要る気質は、arc_* や応答スタイル節に書いてはいけない。**

### 書いたら消えるもの

`stripCharaMetaNoise`（`src/lib/prompt-builder.ts:242`）と
`cleanCharacterInfoText`（`src/lib/character-info-quality.ts:44`）は、UI でキャラを編集して
保存する経路（`parseSystemPrompt` → `buildSystemPrompt`、`ou-edit-screen.tsx:94-98`）で走る。
該当した **文の単位で恒久的に消える**。次の rebuild で戻ってこん。

- `AI` を含む文（`/AI\s*(?:チャット|キャラクター|…)?/`）
- `安全` `倫理` `ガイドライン` `規約` `フィルタリング` を含む文
- 運営・プラットフォーム・システムが主語の `禁止` / `違反`（キャラ本人の「キスは禁止」は残る）
- `制約は一切ない` / `どんな過激な内容でも` / `申し訳ありません`
- `〜してください` `記述すること` `含めること` `出力しないでください`（指示文の形）
- `性格・見た目` `性的特徴プロフィール` `出会いのシチュエーション` `JSON` `以下3項目`
- 行頭 `出典:` `作者:` `★` `[👤`、`※…差分追加`

**この削除は no-injected-ai-filter をデータ層で実装しとる。** 倫理・安全の語がシートへ
入り込めんようになっとる。逆に言うと、シートを人物紹介の散文として書けば消えん。
**指示文の形で書くと消える。**

もう一つ。`ESTABLISHED_RELATIONSHIP_KEYWORDS`（`src/lib/encounter-tension.ts:42`）に
`彼女がい` `恋人` `同棲` `幼馴染` `同僚` 等がある。初対面のキャラのシートにこれらの語が
入ると `isStrangerEncounter` が false になり、**初対面の緊張ブロックが丸ごと消える**。
`0065` 前のシートには `彼女` が入っとった。

## 直したシートが本当に届いたかの確認

`prompt/instructions/adversarial-review-with-codex.md` により、この repo で「直った」と
言うには反証を通らなあかん。シートの変更では次の 4 つが実際に効いた。

1. **通し読み。**1 ターンでは判定でけへん。判定基準は `doc/dogfood/reading-rubric.md`。
   キャラの芯は **通し 10 ターンに 1 回** 当てる（1 ターンだけ渡した実測では
   霜月鈴の 5 行中 4 行が判定不能で返ってきた）。#4 の「反転が一度も起きん」は
   通しで初めて見えた。
2. **症状が出た phase と長さで測る。**変えた文字列がその phase の入力に残っとるかを
   上の strip 表で確かめる。conversation で消える節を直しても erotic の症状は動かん。
3. **測定先に migration が当たっとるかを見る。**`0065` が検証用ローカル D1 へ当たっとらず、
   **12 アーム・275 ターンが全部シートの旧版に対する計測やった。**シートの修正は
   一度も測られとらんかった。テストは全部通っとった。
4. **敵対レビューへ投げる。**同日の監査は、テストが全部通っとる修正群に対して「partial」を
   返した。理由は **変えた文字列が症状の出るターンへ届いてへんかった** から。同じ日の
   自己主張 4 件のうち 3 件が反証で壊れとる（`doc/dogfood/vlong-2026-08-17.md`
   「敵対レビューで壊れた自分の主張」）。

機械で分かる欠陥は先に潰す（課金ゼロ）:

```
pnpm exec tsx script/verify/vlong-dogfood-recheck.ts <dump-dir>
```

### 指示を足して指示追従を直そうとせん

`prompt-edit-discipline` の Gate 0 がそのまま当たる。**既にある指示が守られてへんのに
指示を足すのは doom loop。**この repo で効いたレバーは二つだけやった。

- **位置**（#6: system の中 → ユーザー発言の末尾）
- **削除**（分量ノルマを外す、矛盾する二文の片方を消す、条件を頻度へ移す）

追加が正解になるのは、その情報がどこにも無い時（coverage gap）だけ。

## AI でシートを生成する時

`functions/api/lib/character-generation.ts` が現行の生成器である。設計上の穴が二つある。

### 生成器は機構が読むフィールドを一つも出してへん

出るのは `name` / `personality` / `scenario` / `greeting` / `tags` / `eroticProfile` /
`visualMeta` だけ。**次は全部出てこん:**

| 出てこんもの | 無いと何が死ぬか |
|---|---|
| `名前:` 行 | 名前訂正が無言で無効 |
| `speech_endings` / `verbal_tics` / `forbidden_words` | `[Character voice]` ブロックが出ん |
| `arc_conversation`〜`arc_afterglow` | phase ごとの感情弧が出ん |
| `sensory_focus` | 五感の指定が出ん |
| `エスカレート` 連鎖 | beat sheet が出ん = 段が進まん |

生成器を触るなら、まずここを埋める。埋める時は **段の向きが変わる段を終盤に置く** ことを
生成器へ明示する（#4 の再発を data 側で作らんため）。

### 生成器へ渡すべきこと

- 人物紹介の **散文** として書かせる。指示文（`〜してください`）で書かせると
  `cleanCharacterInfoText` が文ごと消す。現行の system prompt もそう言うとる。
- **気質だけを書かせる。結末を書かせん。**「必ず抵抗する」「最後は受け入れる」を
  生成させると、出来事の層がシートへ焼き付いて後から剥がすのが難しい。
- 合意・境界・倫理の語を入れさせん（`no-injected-ai-filter`: キャラ生成プロンプトに
  「合意」の語がある = VIOLATION）。入っても `cleanCharacterInfoText` が消すが、
  消えた分だけ人物像が薄くなる。
- 初対面のキャラに `彼女` `恋人` `同棲` を書かせん（緊張ブロックが死ぬ）。
- 条件付きの癖を書かせる時は **偽になるターンがあるか** を条件に含めさせる。
  「恥ずかしい時は」は常時真になる。

### 生成物をユーザーへ出す前の検査

```
□ 名前: 行がある（^名前:\s*(.+)$ で当たる）
□ speech_endings / verbal_tics / forbidden_words が実物の文字列で入っとる
   （「丁寧な口調」のようなカテゴリ名やのうて、実際の語尾）
□ エスカレート連鎖が 1 行・2 段以上・向きが変わる段が終盤にある
□ 語彙・台詞に段が付いとる（無段の語彙欄に終盤の語が混ざってへん）
□ 常時真の条件が無い（「恥ずかしい時は」型）
□ 【シナリオ】と【関係性】が同じ時点を指しとる（#3 の型）
□ conversation でも要る気質が arc_* や【シーン中の応答スタイル】に入ってへん
□ 初対面キャラに ESTABLISHED_RELATIONSHIP_KEYWORDS が入ってへん
□ getGeneratedCharacterInfoIssues が policy-heavy / bad-prose を返さん
□ 結末（必ずこうなる）が書かれてへん。気質だけになっとる
```

最後に一つ罠がある。生成器の JSON shape 自身が
`"200-400文字の自然な性的特徴プロフィール"` と書いとる。`性的特徴プロフィール` は
`BAD_PROSE_PATTERNS` に載っとるので、**モデルがこの語を本文へ echo すると
その文が消える**。生成器の文面と自分のフィルタが食い合う形は他にもあり得るので、
生成器の指示語を変えた時は `character-info-quality.ts` の 2 つのパターン表と
突き合わせる。
