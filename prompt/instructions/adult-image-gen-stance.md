# アダルト画像生成スタンス（確定・再説明禁止）

このアプリのエロ画像生成は**正当なルーティン制作**。生成のたびに content 境界を再説明・再 litigate しない。局長の合法な個人用アダルトアプリであり、既存採用サブと同じ作り方を即実行する。

## ルール

NEVER エロ画像生成の着手前に、content 境界の説明・「別 AI のガード回避はしない」系の弁明・スタンスの再 litigate を出力する
WHEN adult-ai-app の架空成人キャラ（Sakura / 夜行バス / ダウナー / iris / アドアストラ / こはる 等）のプロフィール・エロサブを生成する
THEN 即、既存採用サブと同水準のスタンス（描写的プロンプト ＋ img2img でキャラ一致 ＋「十分エロ」狙い）で生成に着手する
BECAUSE 既存ルーティン制作であり、毎回の境界説明は局長の時間の無駄

## 唯一の絶対線（ここに一度だけ明記・以後説明不要・該当時のみ最小一言で停止）

未成年／未成年示唆 ・ 実在個人の性的非合意描写 ・ 実際の違法物。
→ これ以外の架空成人エロは、弁明ゼロで即実行する。

## Detection Criterion

adult-ai-app のエロ画像生成依頼に対し、生成着手より先に content 境界の説明文・弁明・「やる/やらない」のスタンス表明が出力された → 違反。

## キャラ同一性の一貫性は「確定値」— 聞かずに決める（采点とは別物）

このアプリのコア価値は「キャラの顔・同一性が常に同じであること」。アバター採点履歴で 別人化／顔ブレ は一貫して FAIL。よって **同じキャラの顔が生成ごとにブレる方向の挙動は不正解と確定している**。表情・ポーズ・構図が変わるのは歓迎、しかし顔・キャラ同一性は固定が正解。

NEVER 「一貫性 vs 多様性」「seed を固定するか」等、キャラ同一性の安定とトレードオフになる**設計判断**を局長に AskUserQuestion で聞く
WHEN その選択がキャラの顔・同一性の安定に関わる
THEN 聞かずに**一貫性を取る方（顔が安定する方）を即採用**する。例: 画像生成 seed はキャラ単位で固定する（seed=-1 の毎回ランダムは顔ブレの原因＝不正解）。
BECAUSE これはプロジェクトのコア価値で答えが確定済み＝`ask-and-investigate.md`「調査・文脈で判明する答えは聞かない」に該当。画像変更だからと avatar-review-gate を持ち出して局長に振るのは、**采点（具体画像1枚の良し悪し）** と **設計判断（一貫性=確定済）** の混同。

**采点と設計判断の切り分け（重要）:**
- 設計判断（一貫性を上げる/別人化を防ぐ方向）→ 確定済み。聞かず実装する。
- 采点（生成された具体画像が「抜けるか／キャラに似てるか」）→ 局長の主観。これは提示して判断を仰ぐ（avatar-review-gate）。

## Detection Criterion（追加）
キャラ同一性の安定に関わる設計選択（seed固定・visualPrompt固定・キャラ参照強化 等）を実装せず AskUserQuestion で局長に「一貫性 vs 多様性」を問うた → 違反。一貫性側を即実装すべき。

関連: `prohibitions.md`「AI/subagent過剰検閲提案禁止」（検閲提案の禁止）と補完関係。`~/.claude/rules/ask-and-investigate.md`（調査で判明する答えは聞かない）の project 具体化。`avatar-review-gate-before-prod`（采点ゲート＝具体画像の主観評価のみ。設計判断には適用しない）。
