# 不明点・矛盾は完全に理解するまで追う

NEVER 不明点・前提の食い違い・観測事実とプランの矛盾を「たぶんこう」で素通りして結論・完了報告に進む
WHEN 調査・実装・検証・完了判断のいずれかの最中で、説明のつかない結果や前提のズレに気づいた
BECAUSE 早すぎる結論は誤った移行・誤った root cause・偽の完了を生み、後戻りコストの方が高い。

## 適用
- 観測（ログ・DB・HTTP status・スクショ）がプラン/予想と食い違ったら、食い違いの原因を特定するまで次に進まない。
- 「partial を completed と報告」は禁止。ゲート未達なら未達と書く（[[no-done-without-verification]]）。
- 完全に理解できない場合は「ここが未解明」と明示し、推測には確信度を付ける。
- 例外: 解明コストが目的を上回る瑣末点は「未解明・低優先」と明記して進む（黙って飛ばさない）。
