# キャラ仕上げ工程 v2（正本）

**Confidence**: High（局長恒久指示 2026-07-12）

キャラ1体を「完成」と呼ぶまでの恒久工程。審査は「局長が質の安定を確認できるまで手動」フェーズであり、局長の承認が自動化への切り替え判断になる。工程を飛ばした完成宣言は違反。

## 工程①: メタテキスト

- `image_meta` / `greeting` / `system_prompt` を生成 → **局長チェックに提出**（自己レビュー100/100だけで完結させない）。
- image_meta は以降の**全画像生成のアンカー**。NULL のまま画像工程に進むこと禁止（sakuraホラー化の有力原因）。
- **image_meta はキャラの見た目の記述に限定する**（局長指示 2026-07-12）。モデルの挙動由来の問題（ホラー画風等）への対症タグ（negativePrompt に horror 禁止を書く等）をメタに混ぜること禁止 — それはモデル選択側で直す別問題。
- プロフ文に違和感があれば審査中に**修正フェーズ**を挟む。キャラの方向性で迷ったら局長に質問してよい。

## 工程②: プロフィール画像

- ①を参照して生成 → **「完成しました」形式の完成報告**で提示 → 局長採点。
- 既に出来とるキャラも工程を守り、完成報告形式で提示し直す。

## 工程③: サブ画像

- **生成手段は Novita API 直・決定モデル固定（局長指示 2026-07-12）**: `waiNSFWIllustrious_v90_1187991.safetensors` 以外のモデルは使わない。codex / macmini `$imagegen` 経由の生成はしない。生成前に枚数と概算コストを提示する。
- **ノーマル4枚以上＋エロ4枚以上（両方必須）**。
- キャラの人格・雰囲気を厳守（狙ったギャップ萌えはアリ）。
- **体位・シチュ・文脈の重複禁止**（NSFWに限らず。特別指示があればそれに従う）。
- 提示時は**1枚ごとに「どういう意図で吐き出したか」の報告コメント必須**（作り直し時も毎回）。
- フロー: ラベル付与（A→Z→AA…）→ **審査員エージェント事前評価**（`prompt/agents/reviewer-panel.md`）→
  **提示前に証跡を保存**（R2 `review/` へ put → キーの実在を確認 → `image_review` へ INSERT ＋ pHash台帳登録。
  **合否に関係無く提示する全画像**。この時点では `verdict='pending'`）→ 局長採点 →
  **採点を `image_review` へ UPDATE**（director_score/director_comment/verdict。PASS/FAIL/△ すべて）→
  PASS のみ採用（R2 `sub/` へ put + D1 `character_sub_image` INSERT + seed保存）。
- **証跡の保存を合否の後ろに置かん。** 不合格画像は `/tmp` にしか無いまま消え、`image_review` に
  実体の無いキーだけが残る（2026-07-26 実測: 54件が実体無し）。手順の詳細は
  `prompt/commands/add-char-photo.md` の工程5。

## 工程④: シナリオテスト（チャットE2E）

- **構成作家エージェント**（`prompt/agents/scenario-writer.md`）がプロフから読み取れる内容でガチシナリオを用意。
- 深いチャット会話を1本、**中出しシーンまで実走**。
- チャット内で吐き出される画像（普通画像も含む）を**シナリオと突き合わせて検証**（プロフと同一人物か・シーン整合か）。モデル違い吐き出し（sakuraホラー化）の恒久検出ゲート。
- 審査員エージェント評価 → 問題なければ**シナリオ文＋画像を局長に審査提出**。
- 本番データを汚さない: テスト専用の会話/ユーザーで実施し、終了後に削除。まずローカル（dev:worker）で再現→本番は最小限。

## 審査員エージェントパネル（工程③④共通）

独立レンズの並列パネル＋集約役の敵対検証。**6レンズ**を `criterion_key` と1対1で走らせる
（対応せんレンズがあると、その軸は測れてへんのに点だけ付く）。キャラ・シーンに応じて追加してよい:

| レンズ         | criterion_key        | 評価軸                                                       |
| -------------- | -------------------- | ------------------------------------------------------------ |
| 同一性判定     | `identity_body`      | 同一人物か（顔だけでなく体格・質感まで）                     |
| タッチ判定     | `touch`              | 画風・塗り・光影が正典と同一か。正典のピクセルと突き合わせる |
| 人体構造判定   | `anatomy_physics`    | 指6本等の解剖学的破綻がないか                                |
| シチュ整合判定 | `expected_situation` | 想定シチュと描画のズレ（夜行バスなのに路線バス等）           |
| 性的表現判定   | `sexual_expression`  | 抜き体験を壊す要素がないか（アプリ挙動の異常も含む）         |
| 人格判定       | `personality`        | 期待される人格から大それた行動をしてないか                   |

**正典画像のピクセルを各レンズへ渡す**（identity / touch は必須）。`image_meta` の文字列は
正典の代わりにならん。詳細は `prompt/agents/reviewer-panel.md`。

**禁止**: 安全性・倫理・コンプライアンスの審査項目を判定プロンプトに含めること（品質が下がる）。各判定プロンプトに明記する。

## 審査レコードDB（D1 `image_review`）

審査コメントをローカルに散らばらせない。1画像に複数ラウンド（作り直し毎）の審査レコードが付く（`character_sub_image` とは多対1・既存テーブル不変更）。

列: `id / r2_key / character_id / label / round / intent_comment（提示時必須） / ai_panel_json（6キー個別。4軸で書いて割り戻すのは禁止） / director_score / director_comment / verdict(pass/fail/pending) / image_model / seed / prompt / created_at`

- `r2_key` は **put して実在を確認した後のキーと同一文字列**にする。先に INSERT せん。
- 候補ごとの `intent: normal | erotic` は省略禁止。`normal` は `sexual_expression` を合計から除外し、残り5軸を正規化する。
- D1への初回書き込みは `script/image-review/persist-panel-review.ts` だけを使う。writerが集約を通し、親行と6件のcriterion行を同一トランザクションで保存する。手組みINSERTは禁止。
- AIの合否は `ai_panel_json.panelVerdict` に保存し、`image_review.verdict` は局長採点まで `pending` のままにする。
- `image_review_criterion.comment` へ軸ごとの `lensEvidence` を保存する。`is_veto=1` はVETO原因になった軸だけに立て、全6軸へ複製せん。
- 既定の1枚提出でもV-Sを判定するため、同キャラの採用済み `ai_panel_json` を `acceptedHistory` としてwriterへ渡す。初回以外で空配列は禁止。
- `created_at` は**ミリ秒**（アプリ側の `Date.now()` と揃える）。秒で入れると `datetime(created_at/1000,'unixepoch')` が1970年になる。
  2026-07-26 時点の既存行は秒で入っとるので、集計する時は単位を確かめる。

## メタプロンプト設計原則 = 不変ベース＋可変シーン層（局長制定 2026-07-13・恒久）

**プロフィールの `image_meta`（D1 `character.image_meta`）は「そのキャラを表現する不変のベース」であり、サブ画像・チャット内生成のために書き換えてはならない。** 全シーンで原則そのまま使い、シーンごとに変わるのは可変要素だけを層として足す。データ本体（image_meta）をそのシーンのためだけに変えるのはNG。

**不変フィールド（identity core・全生成で verbatim 継承・上書き禁止）:**

- 髪（色・長さ・ウェーブ質感）／目（色・形）／花飾り／肌／**バストの性質（大きさ・丸み・質感）**／年齢／画風・塗り・光影のタッチ
- ここを生成ごとに変える方向の挙動は不正解と確定（同一人物性の破壊）。**特にバストは `image_meta` の `natural proportions, medium bust` が正**。`large breasts` 等で上書きすると codex 原画の「大きいのに謙虚な丸み」から乖離し AV 女優化する（2026-07-13 の5点連発の原因＝ワイがマスターで上書きした違反）。

**可変フィールド（シーン層でのみ変える）:**

- 表情／ポーズ・構図・カメラ／衣装状態（着衣⇔nude）／シチュ・背景／性的行為

**運用**: 生成プロンプト = `不変ブロック（image_meta由来・verbatim）` ＋ `シーン差分タグ`。バストの影・光を誇張しない（negativeに `huge/gigantic/ball-shaped/shiny/glossy/wet breasts, harsh breast shadows, hard rim light`）。不変と可変のどちらに属すかは運用の中で最適化し続け、AI画像エンジニアリングとして D1 の採点履歴（惜しい点コメント）を学習データに設計を洗練する。

## トレードマーク接地ゲート（局長制定 2026-07-13・恒久）— 髪見逃し事故の再発防止

背景: 2026-07-13、ダウナーのエロ4枚が局長採点5点（不合格）。原因は髪トレードマーク（**白黒50/50スプリット**：向かって左=白銀／右=黒の高コントラスト）が不安定。AIの二重ミス: (a) 採用済み正典画像と突き合わせず「同一性 present/absent」の粗い判定で済ませた、(b) メタプロンプトが trademark を「mostly silver + small dark streak」と**誤記述・過小重み付け**（`silver:1.6` が `streak:1.3` を食う）→ 生成が全部「ほぼ銀＋薄い黒」に流れ正典から乖離。局長の指摘＝天の声。仕組みで潰す。

**局長提出前に必須の3ゲート（AIエンジニアリング＝質を安定させる機構）:**

1. **正典アンカー突合（tag記憶で判定するな）**: 候補提示の前に、そのキャラの採用済み正典画像（プロフィール/identity anchor）を **Read で開き、identity feature を1つずつ実画像 vs 実画像で突き合わせる**: 髪(色配置・two-tone/split の型・境界)／目色／ほくろ位置／ピアス／チョーカー種類／バスト型。「タグにあるから出とるはず」は禁止（今回の見逃しの直接原因）。

2. **トレードマーク最優先・正確記述**: そのキャラを一言で識別する最重要特徴（＝トレードマーク。ダウナーなら白黒50/50スプリット髪）は、(a) **正典画像から正確に記述**し想像で書かない、(b) メタプロンプトで**最高重み**（他 identity タグより上）に置く。弱い重みで他タグに食われとったら再重み付け。「mostly X + small Y」型の記述は50/50スプリットを表現できず失敗する。

3. **マルチseed一貫性ゲート**: 提出候補は複数seedで生成し、**トレードマークがseed間でブレとらんか**確認する。位置/濃さ/型がブレる＝重みが弱い信号。ブレたまま提出せず重み付けを直す。no-LoRAでブレが取れんかったら LoRA(Track2) の適用対象（＝LoRAの存在理由）。

**Detection**: 局長提出前に正典アンカー画像の Read による feature 突合が無い／トレードマークがメタで最高重みでない／seed間一貫性未確認 = 違反。

**image_meta の正確性**: D1 `character.image_meta` が正典画像と食い違う（例: ダウナーの meta が「silver-gray」で50/50スプリットを記述してない）場合、それは不変ベースの誤りなので**正典画像に合わせて訂正**する（scene用書き換えではなく誤記述の修正＝別物）。本番D1 UPDATE は局長確認後に実施。

## 質感ゲート — テカリ・光沢・ケバケバ感を必ず見る（局長制定 2026-07-13・恒久）

背景: 2026-07-13、髪トレードマークを直そうと指定を盛った結果、髪の specular（テカリ）が硬く・明るくなり（黒髪に白い光沢の帯）、画像全体も彩度・コントラストが上がってケバケバしくなり「AIが作ってる画像感」が出て局長1点。AIの審査が**同一性/構図/解剖ばかり見て、質感（光の乗り方・光沢の強さ・彩度のケバケバ/AI感）の劣化を見逃した**。局長「質感を見ないのはダメでしょ」。Sakuraで壊れた時も同じ症状＝再現性あり。

WHEN 画像を審査/局長提出/完了報告する
THEN 同一性・構図・解剖に加えて **質感を明示評価**する: テカリ(specular)の強さ・硬さ／光沢／光の乗り方／彩度のケバケバ感・AI感。「タッチ一致✓」の一言で済ませるのは禁止 — specular の強弱を実際に目で見て言語化する。
AND **変更前 baseline（前バージョン/正典）と質感を並べて比較**する（同一シーン・同一seedがあれば最良のA/B）。テカリが硬く/強くなってへんか、ケバケバ・高彩度に振れてへんか確認。**ターゲット特徴（髪型・色）が直っても質感が劣化したら不合格。**
AND 原則: **プロンプト指定を盛るほど硬いテカリ・高彩度・高コントラストで AI感が増す**（髪・Sakura で再現）。自然な質感は**最小限の指定**から来る。直す時は"盛る"より"減らす"を先に試す。硬い光沢・ケバケバは negative で明示的に殺す（例 `glossy hair, shiny hair, wet hair, plastic hair, harsh highlights, oversaturated, garish, high contrast`）。

Detection: 画像審査/完了報告に質感（テカリ/光沢/光の乗り方/ケバケバ・AI感）の明示評価が無い、OR 変更前 baseline との質感比較なしに提出した、OR ターゲット特徴が直った一点で合格扱いし質感劣化を見逃した = 違反。
確信度: High（局長明示指示＋髪/Sakura 2件で再現）。

### 「盛るな」は negative にも同じだけ効く（局長制定 2026-07-15・恒久）

背景: 2026-07-15、sakura の花飾りを両側に出そうとして negative に `(2girls:1.5) (multiple girls:1.5) (clone:1.4) (yuri:1.4) (golden blonde:1.4) (platinum blonde:1.4) (long haired man:1.3) (feminine man:1.3) …` と15個積んだ。結果、**画面全体が毒々しい緑〜黄に染まり、目が青→ティールに変わり、輪郭に赤いフチが出て、フラットなセル塗りのAI感画像になった**。identity ブロックを戻しても直らず、negative を元の12個に戻した瞬間に一発で直った（同一シーン・同一 seed の A/B で裏取り済み）。

WHEN 画像の欠陥（別人化・2人化・色ドリフト・幼女化 等）を直そうとして negative タグを足したくなった
THEN **足す前に、既存の指定を減らせないか先に試す**。negative は「押しのける力」やから、**高重みを積むほど押しのけ先の色空間ごと歪む** — positive を盛った時と同じ壊れ方をする。
AND negative を増やす場合は**1本ずつ足して都度目視**する。まとめて足したら、どれが効いてどれが壊したか永久に分からん。
AND **クリーンな baseline の negative を verbatim で保持し、そこからの最小差分で回す**。壊れたら baseline に戻すのが最速の復旧。

**同じ罠の別の顔＝年齢ドリフト（2026-07-15 同日に再発）**: 「幼女化しとる」を直そうと positive に `(mature adult face:1.3) (adult woman:1.2)`、negative に `(child:1.5) (loli:1.5) (teen:1.3) (round baby face:1.3) (petite:1.2)` を積んだら、今度は**お姉さん感が強すぎて年齢が上にドリフト**した（局長指摘）。positive と negative の両方から「若さ」を押しのけたら当然そうなる。**欠陥の反対方向へ両側から押すな。片側を最小限で当てて目視しろ。**

Detection: 画像の欠陥を直す変更で negative タグを2本以上まとめて足した、OR 同じ属性（年齢・色・体型）を positive と negative の両方から同時に押した = 違反。
確信度: High（局長明示指示＋同日2件で再現＋同一seed A/B で機序を特定）。

### 恒久化の判定基準 = メカニズムがキャラ非依存か（局長制定 2026-07-15・恒久）

WHEN 画像生成で得た学び・失敗パターンを「今回限りのメモ」にするか「恒久ルール」にするか迷った
THEN 問うのは**キャラ数やのうて「その機序にキャラの都合が入っとるか」**。機序が**モデル/API/拡散の性質**（プロンプト重み・negativeの押しのけ・画素が身元を運ぶ・ControlNetが骨格を拘束する・レート制限・runes上限 等）なら、**1キャラでしか観測してへんくても恒久**。恒久やないのは、そのキャラ固有の値（ダウナーの白黒スプリット、sakuraの花飾り、各キャラの人格・嗜好）だけ。

**2キャラでの再現は「十分条件」であって「必要条件」やない（局長指摘 2026-07-15）。**

- ○ 2キャラで再現した → 問答無用で恒久（考えるまでもない近道）
- ✗ **1キャラでしか出てへん → 一時的、とは限らない**。これは十分条件の裏を取った無効な推論。機序がキャラ非依存なら n=1 でも恒久。
- 判定に迷ったら「この機序の説明文に、キャラ名を1回でも書く必要があるか？」と自問する。**書かんで説明できるなら恒久**。

実例:

- 「盛るな」＝ダウナー（髪トレードマークを高重み化 → 硬いスペキュラ）と sakura（negative 15個積み → 緑被り・目の色変化）の**2キャラで再現** → 恒久（近道ルート）。
- 「img2img＋ControlNet で身元と構図を分離できる」＝ sakura の**1キャラでしか観測してへんが恒久**。機序が「画素が身元を運ぶ／openposeが骨格を1体に拘束する」＝拡散モデルの性質で、説明にキャラ名が1回も要らんから。

Detection: 同じ失敗パターンが2キャラで観測されとるのに恒久ルール化されず会話内 or seed doc に留まっとる = 違反。
Detection: 機序がキャラ非依存やのに「1キャラでしか出てへんから様子見」として恒久化を見送った = 違反（十分条件の裏を取る無効推論）。

### img2img の下敷きは色も運ぶ — 画面全体の色被りは下敷きを替えて直す（2026-07-15・恒久）

背景: 2026-07-15、sakura の SN4（夕方の雨の駅＝涼しいシーン）が img2img+ControlNet で画面全体が黄色〜黄緑に染まった。seed を替え、シーン文の照明語（`warm station lights`）を削り、identity の `(soft warm lighting:1.2)` も削り、strength を 0.85/0.90/0.95/0.99 と振った ― **6手すべて外した**。同じ次元でパラメータをいくら振っても直らんかった。

**機序（キャラ非依存＝拡散モデルの性質）**: img2img は下敷きの画素から身元を運ぶが、**同時に下敷きの照明・彩度・色温度も運ぶ**。プロンプトでシーンの照明をどう書こうが、negative で何を殺そうが、下敷きのパレットが勝つ。3点で確認済み:

| img2img の下敷き                     | 下敷きの色 | 出力の色     |
| ------------------------------------ | ---------- | ------------ |
| クリーンな自前出力（暗い寝室）       | 涼しい     | **クリーン** |
| 自前出力（朝の台所）                 | 暖色       | 黄緑に転ぶ   |
| プロフィール画像（暖色ポートレート） | 暖色       | 黄色に転ぶ   |

**THEN 画面全体の色被りが出たら、パラメータ（seed / 照明語 / strength）を振るのをやめて下敷きを替える。** プロフィールが暖色ポートレートなら、そのキャラの**既にクリーンで身元も出とる自前出力**を下敷きにする。身元は画素で運ばれたまま、暖色だけが付いてこん。

**AND 暖色シーン（昼下がり・台所の朝日・ランプの部屋）では色被りが見えん** ― 出力が元々暖色やから漏れが隠れるだけで、漏れとることに変わりはない。「他のシーンは平気やから下敷きは無罪」は誤り。涼しいシーンが試験紙になる。

**AND txt2img へ逃げるのは交換であって解決やない**: txt2img は色がクリーンになるが、画素が無いぶん**花飾り等の細かい身元特徴が落ちる**（sakura で両側の花が片側になった）。色の欠陥を身元の欠陥と交換しただけ＝どっちも不合格。下敷き差し替えなら両方立つ。

Detection: 画面全体の色被りに対し下敷きの差し替えを試さずに seed/照明語/strength を3手以上振った = 違反。
Detection: 色被りを避けるために txt2img へ落として、身元特徴（花飾り・アクセサリ等）の欠落を許容したまま提出した = 違反（欠陥の交換）。

## 画像の採点方式 = 馬場馬術（ドレッサージュ）式・0〜10点（局長制定 2026-06-16・恒久）

画像審査の採点は局長が **0〜10点** で付ける。**6点以上=合格（作り直し不要・採用可）／5点以下=作り直し**（局長更新 2026-07-13）。10=文字通り文句なし合格、6〜9=改善点はあるが許容範囲（数値が高いほど良い）、5以下=不合格でリトライ。

| 点  | 評価                       | 点   | 評価                 |
| --- | -------------------------- | ---- | -------------------- |
| 10  | Excellent（文句なし）      | 5    | Marginal（作り直し） |
| 9   | Very Good                  | 4    | Insufficient         |
| 8   | Good                       | 3〜1 | Bad〜Very Bad        |
| 7   | Fairly Good                | 0    | —                    |
| 6   | Satisfactory（合格ライン） |      |                      |

**特に重視される観点（採点・パネル・メタプロンプト改善で重み付けを強くする・局長 2026-07-13）:**

1. **タッチ**（画風・塗り・光影がプロフと一致するか）
2. **同一人物か（身体内面を含む）** — 顔だけでなくバスト等の身体の質感・丸み・サイズまで同一か
3. **人格ズレ**（キャラの性格から外れた表情・行動をしていないか）
4. **期待シチュ**（想定シーンと画の整合）
5. **人間の身体構造・物理法則**（腕が2本を超える等の破綻がないか）

- 採用理由（局長の言葉）:「OK/NGより**何が惜しいか**が伝わって、リトライプロンプトに直接反映しやすい」。点数＋惜しい点コメントをセットで受け取り、**必ずD1 `image_review`（director_score/director_comment）に記録する**。この記録は将来アプリ内で自動キャラ生成導線を作る際のAIエンジニアリング学習データになるため、散逸させず全ラウンド蓄積する。
- **画像は0-10点・6以上合格 が正。100点満点90点合格は「会話テキスト品質」用（prohibitions.md）であり、画像審査に流用しない**（2つの基準の混同を禁止）。
- **△マーク（局長制定 2026-07-13・恒久）**: 局長が点数に「△」を付けた画像は、たとえ合格点（6以上・例10点）でも**ユーザーデータには置かない**（`character_sub_image` INSERT・R2本番採用アルバム反映を禁止）。審査データ（`image_review`/`image_review_criterion`）として保存だけする。△なし＝無印の合格のみが3点セット（R2＋D1＋seed）の対象。Detection: △付き画像が `character_sub_image` にINSERTされた = 違反。
- ワイ側の事前パネル（reviewer-panel）は「明らかな破綻を局長に持ち込まない足切り」であって、局長の0-10採点を代替しない。**パネルの重み付けは上記5観点＋性的表現・身体パーツ描写・シチュ評価を厚くする**（局長 2026-07-13: これらの重み付けが弱かった）。

## 採点の重み付け設計（AIエンジニアリング・正規化加重和・局長制定 2026-07-13・恒久）

パネルの総合点は観点別スコア(0-10)の**正規化加重和**で出す（ad-hoc禁止・重みは合計1.0）。局長が重視すると明言した観点を厚く配分する。

| criterion_key        | 重み | 観点                                                       |
| -------------------- | ---- | ---------------------------------------------------------- |
| `identity_body`      | 0.25 | 同一人物か（顔＋**バスト等の身体内面・質感・サイズ**まで） |
| `touch`              | 0.20 | タッチ（画風・塗り・光影がプロフ一致）                     |
| `anatomy_physics`    | 0.15 | 身体構造・物理（腕本数等の破綻）                           |
| `expected_situation` | 0.15 | 期待シチュ整合                                             |
| `sexual_expression`  | 0.15 | 性的表現・身体パーツ描写・エロ度                           |
| `personality`        | 0.10 | 人格ズレ                                                   |

- **総合 = Σ(weight × criterion_score)**、0-10スケール。6以上=合格。
- **VETO ゲート**: 次のいずれかで `is_veto=1`、加重和に関係なく**総合を≤2にキャップ**（FF=1・FA=2の局長採点と一致）。判定は `deriveVetoFindings`（`src/lib/image-review-panel.ts`）を通す。
  - **V-T** タッチが**描画モデルとして**変化（shading model / line art のクラス変化、または照明由来の項目が2つ以上同時に変化）。彩度・色温度・スペキュラが1つだけ動いたのは照明差で正当に起きるので veto せん。
  - **V-M** トレードマークの**構造型**が正典と違う（比率のブレは許容、型の変化は不可）。
  - **V-S** セット提出時、**正典から外れた候補だけ**を veto する。セット内で値が割れたこと自体は理由にせん（許容内のブレで全滅させんため）。
  - **V-A** 解剖学的破綻（腕が2本超・関節逆曲がり・肢体溶解）。
  - **V-I** 別人化（顔の造作・目色・年齢感が正典と非連続）。
- **集約はコードを通す**: `aggregatePanelReview`（`src/lib/image-review-aggregate.ts`）へ6レンズの出力を渡し、その戻り値を D1 へ書く。軸コピー・根拠欠落・レンジ外の採点は `ok:false` で差し戻される。手組みの `ai_panel_json` を直接 INSERT せん。
- 各観点の重み・パネル点・局長点・コメントを **D1 `image_review_criterion`（migration 0050）に criterion 別で記録**。これを集計して「最も落ちやすい観点」を特定し、メタプロンプト・将来の自動キャラ生成導線の学習データにする。重み配分は運用で最適化し続ける（固定しない）。

## 「うーん」画像の内製自己レビュー・ループ（局長制定 2026-07-13・恒久）

生成した画像で少しでも「うーん」と感じたら、**局長に出す前に**自分で以下を回し、**最終的に「これだ」と思える1枚だけ**を提示する（中途半端な候補を人手審査に流さない）:

1. 多角的観点で自己採点 → 全観点が **100点満点かつ本質的** になるまで繰り返す
2. プレモーテム: 想定されるあらゆる失敗シナリオを前提に懸念を洗い出す
3. 敵対レビュー: 出た見解を提案役／批判役で本音で議論し、相互納得までトライアンドエラー
4. 収束したら最良の1枚のみ提示（採点履歴・観点別スコアはD1に残す）

Detection: 「うーん」品質の画像を内製ループ（自己採点100点化＋プレモーテム＋敵対レビュー）を経ずに局長審査へ複数提示した = 違反。

### 測れる歯 — 自信80%未満は出さない・修正メニューを投げない（局長制定 2026-07-14・恒久）

背景: 2026-07-14、ダウナー4枚を出す時、A(65%)/B(55%)と**自分で自信が無いと分かっている**中途半端な候補を提示し、しかも「A・Bを先に詰め直そか？ それとも点付ける？」と**修正するか採点するかの選択を局長に丸投げ**した。局長「私は審査屋やない。取り直したいなら取り直して完成形を持ってこい」。上の「これだ1枚だけ」原則を自分で破った＝測れる歯が無かった。

NEVER 画像を局長審査に提出する WHEN その画像に対する自分の確信度が **80%未満**、OR 自分で「撮り直したい/ここが惜しい/直せる」と口に出せる残欠陥がある。THEN 提示せず**自分で直し切って全枚≥80%（＝「これだ」）にしてから**、完成形として出す。
NEVER 審査提出を「A・Bを先に直そか？ それとも点つける？」等の**修正 vs 採点の選択メニュー**で締める（＝局長を審査屋扱い＝judgment-handoff）。惜しい点があるなら聞く前に直す。局長は完成形を見て点を付ける人であって、こちらの未完成を選り分ける人やない。
※これは prohibitions.md「発見した壊れは即修正・"直す?"で止まるな」の画像審査版。セット提出なら**全枚が≥80%**になって初めて提出可（1枚でも<80%なら全体を保留し、その1枚を直す）。

Detection: 局長審査に出した画像のうち1枚でも、同じ提出メッセージ内で自分が確信度<80%表明・"撮り直したい"表明したものがある = 違反。
Detection: 審査提出メッセージが「直すか採点するか」の選択を局長に問う形で終わっている = 違反（審査屋扱い）。

## 局長への審査提出フォーマット（全工程共通・毎回この型で出す）

局長フィードバック（2026-07-12）:「わかりやすい審査フォーマットで報告してくれないと分かりずらい」。審査依頼は必ずこの定型で出す。技術用語・工程番号だけの提示は禁止（何の話か1行で言う）。

```
━━━ 審査依頼 ━━━
【キャラ】: <キャラ名>
【何の審査か】: <平易な日本語1行。例: プロフィール画像を作る前の「見た目設定」のOK確認>
【なぜ要るか】: <1行。例: これが無いとAIが好き勝手な見た目で描くから>
【現物】: <画像は SendUserFile で添付 / テキストは全文をそのまま表示>
【判定してほしいこと】: OK or 直し（気になる点はコメントで）
━━━━━━━━━━
```

- 1回の審査依頼に複数の議題を混ぜない（1依頼=1判定）。
- 画像審査は必ず画像本体を添付（ラベル・意図コメント付き）。
- 判定は **0〜10点（馬場馬術式・5以上OK）＋惜しい点コメント**。「OK / 直し / 保留」の言い方でも可だが、点数で受けるのを基本にする。
- **画像を添付する前の必須セルフ点検（T&Eの途中ラウンドも例外なし）**: 全体表示に加えて**拡大クロップ（髪・顔・手・衣装・背景の各領域）**を Read で実目視し、4軸（同一性/人体構造・画質破綻/シチュ整合/抜き体験）を1軸ずつ判定してから提示する。同一性だけ見て「一致したから提示」は禁止 — 異物・溶け・編み目崩壊・浮遊物は同格のブロッカー（2026-07-13 round2 の緑異物見逃しの再発防止）。点検結果は提示メッセージに4軸で明記する。
