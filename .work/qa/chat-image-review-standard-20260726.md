## 1. 審査に入る前の門（機械判定・人手ゼロ）

**この4つが全部通るまで、パネル評価も局長提出もせん。** 1つでも落ちたら生成をやり直す。
理由: 過去の不合格の大半は「見れば分かる欠陥」やのうて「正典と並べて初めて分かるズレ」で、
並べる前に採点しても意味が無いため。

| 門 | 条件 | 落ちた時 |
|---|---|---|
| G1 モデル | `image_model` が `waiNSFWIllustrious_v90_1187991.safetensors` または別名 `aiadultapp:waiillustrious@9` | 生成やり直し。他モデルは審査対象外 |
| G2 身元アンカー | `image_meta` / `character_visual` / `visual_prompt` のどれかが非空 | 生成せん（本PRで 422 を返すよう実装済み） |
| G3 seed | 生成に使った seed が判明しており `image_review.seed` へ入る | 記録せん。再現できん審査は学習データにならん |
| G4 正典 | そのキャラの正典画像（プロフィール/採用済みサブ画像）のR2キーが取れる | 比較審査ができんので提出せん |

## 2. パネル評価 — 単体採点を禁止し、必ず正典と並べる

**変更点はこれ1つ**: 各レンズは「候補画像だけ」やのうて **「正典画像＋候補画像の2枚」** を
受け取り、**差分**を言語化してから点を付ける。重み・VETO・スケールは既存のまま。

| criterion_key | 重み | 何を見るか | **必須の比較記述**（これが無い採点は無効） |
|---|---|---|---|
| `identity_body` | 0.25 | 顔＋バストの質感・丸み・サイズまで同一人物か | 正典のバスト形状と候補のバスト形状を、大きさ／丸み／影の硬さの3語で対比して書く |
| `touch` | 0.20 | 画風・塗り・光影がプロフ一致 | 線の太さ／塗りの階調／ハイライトの硬さを正典と対比。「タッチ一致✓」の一言は無効 |
| `anatomy_physics` | 0.15 | 指6本・腕3本等の破綻 | 拡大クロップ（手・足・背景の接合部）を見た上で書く |
| `expected_situation` | 0.15 | 想定シチュと画の整合 | シナリオ文の場所・時間帯・天候と画を1つずつ突合 |
| `sexual_expression` | 0.15 | 性的表現・身体パーツ描写・エロ度 | 期待した行為・体位・露出段階と画を突合 |
| `personality` | 0.10 | 人格ズレ | キャラの人格記述から外れた表情・仕草が無いか |

- 総合 = Σ(weight × criterion_score)、0〜10。**6以上=合格**。
- **VETO**: `anatomy_physics` か `identity_body` に致命的破綻（腕が2本超・別人化）→ `is_veto=1`、
  加重和に関係なく総合を **≤2** にキャップ。
- **質感の独立チェック（合否とは別に必ず書く）**: テカリ(specular)の強さ・硬さ／光沢／
  彩度のケバケバ感・AI感。**正典と並べて**、硬く・明るく・派手に振れとらんか。
  ターゲット特徴が直っても質感が劣化しとったら不合格。

### パネルのキャリブレーション（Aへの対処）

パネルは今のところ**信用でけへん**（0/9）。当面は次の運用にする。

1. パネルの加重和は**合格の根拠にせん**。合格判定は局長の0〜10点のみ。
2. パネルの役割は「明らかな破綻の足切り」に限定し、**VETO 判定だけを採用**する。
3. パネル点と局長点の**両方を `image_review_criterion` に入れる**（今は director 側が全NULL）。
   10件ほど溜まったら乖離を集計し、乖離が大きい観点の判定プロンプトを直す。
4. パネルが「全部8点前後」に張り付いとる間は、パネルの改善が終わるまで自動化へ進まん。

## 3. 局長提出

- 提出前に**全枚が自分の確信度80%以上**。1枚でも下回るなら全体を保留して直す。
- 「直すか採点するか」を局長に選ばせる形で締めん。
- 提出フォーマットは char-approval-process.md の定型（審査依頼ブロック）をそのまま使う。
- 1依頼=1判定。複数議題を混ぜん。

## 4. 記録（D1 `image_review` / `image_review_criterion`）

PASS/FAIL によらず**毎ラウンド記録する**。記録が無い完了報告は違反。

必須列: `r2_key` / `character_id` / `label` / `round` / `intent_comment` /
`ai_panel_json` / `director_score` / `director_comment` / `verdict` /
`image_model` / **`seed`** / `prompt`

**今回追加する記録規律（C〜Fへの対処）:**

- `director_score` は **0〜10 の整数のみ**。100点満点は会話テキスト品質用で、画像には使わん。
- `image_review_criterion.director_score` を**必ず埋める**（現状 全60行 NULL）。
- `seed` を必ず埋める。`character.seed` が NULL でも
  `deriveCharacterImageSeed(characterId)` で決定的に導出できるので「不明」は無い。
- `image_model` は**モデルID文字列そのまま**。散文の説明を入れん。
- △付きは `character_sub_image` へ INSERT せん（審査データとしてのみ保存）。

## 5. チャット内画像の追加観点（工程④）

チャット生成はプロフィール画像と**別経路**で、過去に唯一残っとる `CHAT-TE` 6件は全部 fail。
サブ画像と同じ基準に加えて次を見る。

1. **プロフとの画質ティア一致** — 局長の不合格理由がこれ（「人物は同じかもしれないが
   プロフ画像と明らかに壊れてる」）。正典と並べて解像感・線の質・塗りの階調を対比する。
2. **シーン整合** — チャット本文が指定した場所・時間帯・服装状態と画が合うとるか。
3. **フェーズ整合** — conversation で脱いどらんか、climax で着衣のままやないか。
4. **色被り** — 画面全体が黄／緑に転んどらんか。**涼しいシーン（夜・雨・冬）が試験紙**。
   暖色シーンでは漏れが隠れる。
5. **色被りが出た時の手順** — seed / 照明語 / strength を振らん。**img2img の下敷きを
   替える**（暖色のプロフィール画像やのうて、クリーンな自前出力を使う）。
   パラメータを3手以上振ったら違反。

## 7. 変えていない所

重み配分（`identity_body` 0.25 / `touch` 0.20 / `anatomy_physics` 0.15 /
`expected_situation` 0.15 / `sexual_expression` 0.15 / `personality` 0.10）、
VETO の ≤2 キャップ、0〜10点で6以上合格、△マークの扱い、判定プロンプトへ
安全性・倫理軸を入れない禁止 — これらは char-approval-process.md のまま。

重み配分が妥当かどうかは**まだ判断でけへん**。観点別の局長点（`director_score`）が
1件も入っとらんので、どの観点が実際に落ちやすいかを集計する材料が無い。
上記の記録規律で10件ほど溜めてから見直す。
