# 年齢格付と公開審査要件の整合（RIT-201）

RIT-134（アダルト対応）の一環として、現状の年齢ゲートと配布経路ごとの審査要件を整理し、
セーフモード切替（RIT-199）の設計が抱える審査リスクを明記する。

## 現状のゲート構成

| 層 | 実装 | 性質 |
|---|---|---|
| サイト全体 | Cloudflare Pages 前段の HTTP Basic 認証（`apps/v2/src/server/basic-auth.ts`、secret は `BASIC_AUTH_USERNAME` / `BASIC_AUTH_PASSWORD`） | 知る人だけ入れる簡易門。年齢を問う機構ではない |
| 年齢確認 | なし（18 歳確認の自己申告画面・外部年齢認証ともに未実装） | — |
| コンテンツ側 | セーフモード設定 `v2_user_settings.safe_mode`（既定 OFF＝アンリミテッド）でモデルチェーンを切替 | ユーザーが `/api/settings` から自由に切替可能。年齢認証とは無関係 |

つまり現状は「Basic 認証を抜けた人は全員アンリミテッド既定で使える」状態。
個人用途としては成り立つが、公開配布としては年齢ゲートの要件を満たしていない。

## 配布経路ごとの審査要件

| 経路 | 成人向けコンテンツの扱い | 整合の見通し |
|---|---|---|
| Web 直配布（現行 Cloudflare Pages） | サイト自身の運用次第。日本国内向けなら 18 禁表記と入口での年齢確認が実務上の最低線。決済を載せるなら各決済事業者の規約が実質の審査になる | Basic 認証を外して公開するなら、入口に生年月日または年齢確認の自己申告ゲートを足す必要がある |
| PWA（ホーム画面追加） | 中身は Web と同一。ストア審査を通らないので成人向けのまま配布できる数少ない経路 | 現行構成の延長で一番現実的 |
| App Store / Google Play | 露骨な性的コンテンツは配布禁止（規約上明確）。セーフモード既定 ON＋サーバ側強制でも「アダルトアプリの抜け殻」としてリジェクトされる実例が多い | 非現実的。アンリミテッド経路を切り離した別アプリにするなら話は別 |
| DMM / FANZA・DLsite 等の成人向けプラットフォーム | プラットフォーム側が年齢認証と審査を持つ。作品・機能ごとの個別審査あり | 進出するならプラットフォーム規約の個別確認が必要（未調査） |

## セーフ切替の審査リスク

- セーフモードは設定 UI からログインユーザーが自由に ON/OFF できる。年齢認証と連動していない。
- 「既定セーフ・成人確認済みユーザーのみアンリミテッド解放」の形にしない限り、公開配布の審査では
  「年齢確認の無いアダルトコンテンツ提供」と見なされるリスクが残る。
- 仮に将来ストア系へ出す場合は、セーフモードをクライアント設定ではなくサーバ側権限
  （年齢認証済みフラグ）に昇格させる再設計が必要になる。現行の `v2_user_settings` は
  あくまでユーザー利便の切替であり、ゲートとしては使えない。

## 結論

- 個人利用（現行の Basic 認証運用）では追加対応は不要。
- 一般公開を目指す場合の最小要件は「入口の年齢自己申告ゲート＋18 禁表記」。
- セーフモードの年齢連動・サーバ側強制化は、配布方針が決まった時点で別 SBI として扱う。
